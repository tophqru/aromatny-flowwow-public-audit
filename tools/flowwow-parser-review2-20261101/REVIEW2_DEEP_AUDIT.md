# Flowwow Parser Review2 — фактические проверки 01.11.2026

## Контрольная точка

Исходный Review1: 41 offline-тест PASS. В Review2 добавлены 2 модуля (`scroll_logic.py`, `category_logic.py`), 11 отдельных mock-тестов и улучшен `capture.py`. После изменений 52/52 offline unit tests PASS, `compileall` PASS. Испытание на реальном Flowwow / GUI Windows 10 / Edge: **NOT_PERFORMED**. Фотографии, cookies, токены, SQLite и приватный репозиторий в публичный пакет не входят. Расширение логики основано на анализе исходного кода и смоделированных сценариях, не на реальной DOM-структуре Flowwow.

## R7 — HIGH: пролистывание магазина одним прыжком

Было: `expand_shop()` вызывал `window.scrollTo(0, document.body.scrollHeight)` и ждал 1600мс; при ленивой загрузке, виртуализации, пропуске видимых промежуточных карточек мог пропустить часть каталога. Исправлено: `scroll_logic.sweep_incrementally` пролистывает по ~0.8 высоты окна, между шагами сохраняет ссылки, виденные в DOM, в SQLite, делает два наблюдения на нижней границе и останавливается при лимите шагов. Тесты: virtualized-items, limits, post-click traversal.

**Осталось:** вложенные scrollable контейнеры, IntersectionObserver с длительным ожиданием и динамический перенос кнопок не доказаны; свойство `observed_document_bottom` не доказывает полный Seller inventory.

## R8 — HIGH: «Показать ещё» не ограничивалась каталогом и не обрабатывала ссылки

Было: кнопка искалась глобально по странице и могла оказаться контролом другого раздела; ссылки не поддерживались. Теперь поиск только в уникальном `<main>`, ARIA role `button` или `link`, точный whitelist надписей; если несколько подходящих элементов — остановка с `AMBIGUOUS_SHOW_MORE_CONTROLS`. Тесты: button, link, ambiguity, reviews, missing main. **Осталось:** кастомный виджет без ARIA или текст на иностранном языке может не обнаруживаться; поиск кнопок не привязан к реальному контейнеру карточек.

## R9 — MEDIUM: категории брались только из устаревшего snapshot

Было: `shop_categories` только из полей `source_category` 66 исходных карточек. Добавлено консервативное чтение явных табов/категорий в `<main>`; запрещаются внешние category links, результаты сохраняются в журнале. Категории с иными DOM-структурами не гарантируются. Признак `all_categories_proven_complete` остаётся `false`. Добавлены четыре теста на вкладки, чужие ссылки, лишние контролы и header.

## R10 — HIGH: переход категории мог увести к другому продавцу

После клика проверяется, что адрес остаётся внутри пути канонической витрины. При выходе — `BrowserBlocked`, прекращение сеанса, никакого включения чужой карточки. **Открытый риск:** категория внутри сайта может иметь законный альтернативный route, которого код не знает; потребуется реальный GUI тест и адаптация по проверенному DOM, без ослабления seller-проверки.

## R11 — HIGH, НЕ ИСПРАВЛЕНО: галерея может быть неполной

`gallery_candidates()` читает `<img>` из одного предполагаемого контейнера. Если оригинальные кадры появляются только при открытии fullscreen, кликах по стрелкам/миниатюрам, в CSS background или при отдельном lazy-load, программа сохранит только видимые кандидаты. **Не разрешается объявлять полноту оригинальных галерей**, пока нет доказанного обхода каждого кадра и сравнения с UI/owner source.

## R12 — HIGH, НЕ ИСПРАВЛЕНО: медиа через APIRequestContext не поточные

`response.body()` может поместить в память весь ответ до проверочного лимита 18 МиБ, если Content-Length отсутствует/неверен. Нужен потоковый ограниченный downloader с жёстким URL/CDN allowlist, безопасными redirect и cookie boundaries. Сейчас по одному файлу, но «жёсткий лимит памяти 18 MiB» утверждать нельзя.

## R13 — MEDIUM, НЕ ИСПРАВЛЕНО: несколько GitHub API чтений из подвижной ветки

Public snapshot и discovery загружаются по `BASE_BRANCH`, HEAD может смениться между запросами. Требуется закрепить **один commit SHA на всю сессию**, сохранить его в `baseline-origin.json` и проверить данные на принадлежность одному revision. Также нужен fail-closed режим при части недоступных discovery, вместо «тихого» пропуска.

## R14 — MEDIUM, НЕ ИСПРАВЛЕНО: счётчик SKU в витрине включает чужие рекомендации

`shop_item_links()` извлекает любые product links из всего DOM, в том числе рекомендации. Каждую страницу затем проверяет seller click, но число найденных shop ссылок не следует считать доказательством принадлежности магазину. Отделить source=`shop_card_in_category` от source=`recommended/unknown` после фактического DOM-исследования.

## R15 — MEDIUM, НЕ ИСПРАВЛЕНО: невидимая загрузка и нестабильность

Стабильное число ссылок и отсутствие `Показать ещё` — не доказательство конца списка. Вплоть до `show more` после отдельного scroll container/вкладки. Нужны доказательства UI-тестов на реальных категориях и контрольные снимки состояния до/после по каждому разделу.

## R16 — LOW/MEDIUM, НЕ ИСПРАВЛЕНО: отчёт после частичного обхода

После bounded stop программа завершает `crawl` без отдельного кода «все категории не доказаны», но событие сохраняется. Для автоматизированного orchestration стоит возвращать отдельный soft-partial code/summary, не считать exit 0 доказательством всего каталога.

## Обязательные приёмочные тесты для Arena

1. Локальный HTTP fixture со стабильным и бесконечным скроллом, виртуализированными карточками, delayed lazy-load, несколькими блоками `more`, nested scroll, 3 различными категориями, ошибочной категорией и карточками чужого продавца.
2. Пройти 2 живых SKU на Windows headed browser, только при реальном доступе; доказать seller click и frame count, не создавать фиктивные результаты.
3. Добавить тесты аварий: SQLite kill/restart, повторная загрузка, SHA corruption, partial JPG, вкладка закрылась, 401/403/429, CDN 3xx, OOM-ограничение, неверная кодировка/кириллица Windows PowerShell 5.1.
4. По каждому изменению — входные данные, воспроизводимый FAIL до правки, PASS после, точный лог и sha. Без доступа к Flowwow = `NOT_PERFORMED`.

**Важно:** Flowwow-источник и публичные данные магазина не изменены. Никаких auto-merge, main, production, Seller prices, stock, orders, sale flags. Автоматическая публикация товаров запрещена.
